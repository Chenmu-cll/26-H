

# 2026 电赛 H 题 K230 视觉模块任务大纲

> 设备：亚博智能 K230 视觉模块
>
> 识别方式：AnchorBaseDet 单类别目标检测（`ball`）



## 题目背景

本程序用于“车载平衡滚球运动控制系统”的视觉部分。摄像头拍摄摆杆凹槽内的钢球，K230 检测钢球位置并计算横向速度，通过串口把数据交给下位控制器。



## 任务要求

K230 只完成视觉识别和数据发送，具体包括：

1. 检测白色塑料管中钢球的横向位置。
2. 连续识别到 2 帧钢球后开始计算横向瞬时速度；正常使用最近 3 帧位置，发生丢失后使用重新识别到的最近 2 帧位置。
3. 按固定协议通过 UART1 发送方向、位置和速度。

本程序不包含：

* 摆杆电机控制；
* 小车循线；
* 钢球闭环控制；
* 无线图传、录像和回放。

## 外设初始化

程序上电后先等待 2 秒，并在等待循环中响应 IDE 中断；等待正常完成后蜂鸣器长鸣1声（600ms），随后关闭 RGB LED 并初始化 UART1、摄像头和 LCD。

| 项目     | 当前配置                         |
| -------- | -------------------------------- |
| UART     | `UART1`，115200 bps，8N1         |
| UART TX  | PIN 9，`UART1_TXD`               |
| UART RX  | PIN 10，`UART1_RXD`              |
| 显示预览 | 通道 0：640 x 480，YUV420        |
| 推理图像 | 通道 2：640 x 480，RGB888 planar |
| 模型输入 | 320 x 320，等比例缩放并填充灰边  |
| 显示器   | `Display.ST7701`，640 x 480      |
| 检测类别 | `ball`，置信度阈值 `0.5`         |

退出时程序会按 `sensor.stop()` → `Display.deinit()` → `MediaManager.deinit()` 的顺序释放资源。



## 数据包格式

串口以 ASCII 字符串形式发送，每帧一条消息，以 `\r\n` 结尾：

- **检测到球**：`origin:(<偏移>)\r\n`  
  `<偏移>` 为球心横坐标与画面中线（320 px）的差值，单位像素，左负右正。

- **未检测到球**：`origin:(999)\r\n`  
  `999` 表示当前帧未找到小球。

## 工作流程

1. 启动相机，获取 640 x 480 的 RGB888 planar 图像。
2. 将图像等比例缩放、填充到 320 x 320，输入 KPU 模型。
3. 使用 AnchorBaseDet 后处理得到钢球检测框。
4. 选择置信度最高的检测框，计算其中心横坐标 `center_x`，再经迟滞状态机滤除静止抖动并确认移动状态。
5. 连续识别到第 2 帧即计算无符号速度；正常使用最近 3 帧坐标，丢失后重新识别时使用最近 2 帧坐标。
6. YOLO 线程每 25 ms 用原始 `center_x` 和滤波后的有符号速度校正卡尔曼状态；UART 线程每 10 ms 预测、封装并发送数据包。



## 注意事项

* 上电等待1500ms用于响应IDE中断，完整后蜂鸣器长鸣一声（700ms）。
* 位置是图像像素坐标，不是厘米坐标。迟滞状态机在 `STATIC` 态使用 7 px 死区，连续 3 帧确认方向后进入 `MOVING` 态；`MOVING` 态连续 5 帧相邻位移不超过 7 px 时回到 `STATIC`。移动时可通过 `EMA_ENABLED` 开关启用 `EMA_ALPHA = 0.95` 的 EMA。
* 速度是绝对值，不含左右方向；方向由 `reserved` 字段给出。
* YOLO 推理线程以 `25 ms` 为目标周期运行。每次得到钢球框后，将**原始 YOLO 中心横坐标**和由迟滞/位置 EMA 后坐标计算、再经速度 EMA 平滑的**有符号像素速度**一起校正二维常速度卡尔曼状态 `(x, vx)`。
* 独立的 UART 预测线程每 `10 ms` 读取该状态并外推一次，因此串口形成目标 `100 FPS` 的 16 字节数据包。卡尔曼状态和速率统计由锁保护；相机、KPU 和 LCD/OSD 仍只在 YOLO 线程中访问。
* OSD 每 `100 ms` 绘制一次最新检测图像，额外标注实际 YOLO 频率、预测包频率和当前滤波后的小球瞬时像素速度。频率按 1 秒窗口更新。
* 检测空帧连续不超过 4 帧时，维持卡尔曼预测；超过 `125 ms` 未收到新的有效观测后，UART 线程发送无效包。重新连续检测到第 2 帧后恢复有效速度。
* 速度由迟滞状态机输出的滤波后位置计算。串口性能统计默认关闭，避免 IDE 日志干扰 25 ms 调度；如需诊断，可在 `config.py` 打开后每 30 帧输出一次阶段耗时。
